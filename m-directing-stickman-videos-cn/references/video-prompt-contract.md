# 模型无关的视频 Prompt 合同

当前短文和分段预案已获批准，配音文件已存在并测量 T 后使用。若音频受阻，可交视频 Prompt 草案，但状态须标 `audio_blocked`，不能声称完整交付。

落每一拍时同时应用 `visual-semantics.md`：具体对象可辨认，动作与口播的施受关系一致，颜色和图标的语义跨段稳定；没有回片时只记录设计检查，不报视觉验收。

## 每段独立文件

每个 C01–CNN 保存一份可复制 Prompt，默认写英文画面指令；中文口播和对齐注记放在代码块外。每份都包含：

1. 适配字段：目标约 10 秒、画幅、所选模型实际支持的帧率/尺寸、静音或丢弃原生音轨要求。未选模型时只写目标，不伪造参数或能力。
2. 所选画风和完整角色锁；色彩只用普通颜色词。
3. `FIRST FRAME`：C01 的初始画面；C02 起写“使用上一段实际生成且已验收的尾帧作为本段首帧图像输入”，并重复上一段末帧的文字状态。图像槽名称随实际模型填写；Prompt 中写了文件名不等于已上传。
4. 三拍 `[0–3s]`、`[3–7s]`、`[7–10s]`：每拍先写对应口播的英文语义意图，再写具体可见动作。语义说明不得变成朗读文本或画面字。
   - C01 需在 `[0–3s]` 或 `[3–7s]` 的前 2 秒内明确写出黄金钩子的画面动作，并注明 `hook_visible_by: 5s`；这项计划不能替代生成视频后的实测。
5. `FINAL FRAME`：描述角色姿势、道具、背景、构图与运动是否停止，为下一段提供可辨认尾态。下一段首态逐项一致。
6. 通用和画风专属负向约束：无可见字/字幕/伪字、无无关角色和形变；Style 1/Style 2 的服饰限制分开。

将已批准分镜的至少四种相关视觉手段落实到三拍，约每 2–3 秒有一次可感知变化。动作以角色与具体道具的物理互动驱动，避免抽象液体变形或角色长时间静止；不要把视觉密度写成画风、线宽和角色身份快速切换。

每段 Prompt 必须自包含，不用“同上”省略角色。视频模型不限 Gemini；如果选定模型不支持以真实图像作为首帧输入，该模型不能承担这条连续链，应更换支持的模型或标 `continuity_blocked`。模型能接图仍不保证尾帧或角色稳定，实际效果留待外部视频生成后的视觉验收。

## 接口表与状态

接口表逐行列 `clip`、本段末帧文字状态、下段首帧文字状态、真实尾帧文件（未取得则空）、下一段图像输入槽、状态。预先写完所有 Prompt 时，C01 可标 `prompt_complete`；C02–CNN 的文字 Prompt 可标 `prompt_complete`，其图像输入另标 `awaiting_previous_tail_frame`。外部视频生成者回填真实尾帧后，才可标 `frame_bound`。文字匹配、文件存在、上传成功和实际画面连续是四件不同的事。
